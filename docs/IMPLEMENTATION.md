## 검증

| 검사                          | 결과                                                                                            |
| ----------------------------- | ----------------------------------------------------------------------------------------------- |
| TypeScript strict             | 통과                                                                                            |
| Vite 네 개 HTML 프로덕션 빌드 | 통과                                                                                            |
| Vitest                        | 38개 통과: 순수 함수 3, 생성기 14, 편집 가능한 코드 예제 구문 21                                |
| Playwright Chromium           | 14개 통과: 데스크톱 7, 모바일 에뮬레이션 7                                                      |
| Storybook 정적 빌드           | 통과                                                                                            |
| 생성 프로젝트 독립 검증       | 세 템플릿 × 옵션 포함/제외 = 6개 설치·타입·프로덕션 빌드 통과; 테스트 포함 3개 단위 테스트 통과 |
| 화면 확인                     | 데스크톱 갤러리, 모바일 라이브러리, Cloudscape 다크 모드 확인                                   |

브라우저 시나리오는 갤러리 검색/상세/뷰포트/테마 유지, Props 및 disabled, 모달 Escape 닫기, CMS 생성/수정/삭제/CSV, Cloudscape 생성/검색/상태 전환, Analytics 필터/KPI, ZIP 다운로드/안전한 이름, 파일 선택과 레이아웃을 다룹니다. Safari/WebKit 및 Firefox는 실행하지 않았습니다. Storybook a11y 애드온 구성은 전체 접근성 감사를 통과했다는 의미가 아닙니다.

검증 환경에는 두 가지 제한이 있었습니다. Storybook이 OS 네트워크 인터페이스 조회에서 실패하여 검증 프로세스에만 loopback fallback을 적용했습니다. 해당 우회 코드는 프로젝트 소스에 포함하지 않았으며 일반 OS에서는 표준 명령을 사용합니다. Playwright 다운로드의 기본 CDN은 잘못된 ZIP을 반환했지만 공식 대체 다운로드 호스트에서 Chromium을 설치하여 실제 테스트를 완료했습니다. 사용 버전은 1.56.1로 고정했습니다.

## 알려진 제한과 남은 작업

- Props 패널은 공통 레이블, Button의 variant/size/disabled/loading과 일부 입력/폼 상태를 지원합니다. 모든 컴포넌트 Props를 자동 추론하는 스키마 에디터는 아직 없습니다. 테이블·필터·탭 등은 미리보기 안에서 상태를 직접 조작합니다.
- Storybook은 Button 상태별 스토리와 모든 예제를 고를 수 있는 Controls 스토리를 제공합니다. 모든 컴포넌트의 개별 exhaustive story·interaction test는 후속 작업입니다.
- Cloudscape 번들은 큰 청크 경고가 있습니다. iframe으로 스타일을 격리했지만 네트워크/청크 최적화는 추가로 진행해야 합니다. 한국어 웹폰트를 포함하고 Cloudscape의 공식 typography token을 런타임에 적용합니다. 빌드 시 테마 생성으로 바꾸는 최적화도 후속 항목입니다.
- CMS·Cloud는 메모리 Mock이며 새로고침 시 초기화됩니다. Analytics 데이터는 결정적 샘플이고 비교 증감률과 유입 비중은 고정 예시입니다.
- FileUpload는 다중 선택·용량 검증·파일명 표시를 제공합니다. 서버 전송, 파일 보관, 업로드 진행률은 구현 범위에 없습니다.
- ZIP 생성기는 현재 제공되는 세 템플릿만 지원하며, 사용자 정의 템플릿 등록/메타데이터 편집/권한 관리는 없습니다.
- 전체 WCAG 감사, 실제 보조기술 검증, 브라우저 다양화 및 E2E 커버리지 확대가 남아 있습니다.
- 백엔드, DB, 인증, 배포는 추가하지 않았습니다. GitHub Actions에는 재현 가능한 검증 명령을 정의했습니다.

## 디자인 탐색 및 백엔드 개발자 가이드 확장

- 좌측 메뉴를 Workspace / Design Studio / Components / Tools로 분류하고 17개 목적별 메뉴를 제공합니다.
- `/design`: 버튼 6개, 카드 3개, 입력 필드 3개로 구성한 12개 디자인 프리셋을 탐색합니다.
- `/design/buttons`, `/design/cards`, `/design/inputs`: 스타일, 6색, 크기, 모서리, 그림자, 상태, 너비를 조정합니다. 버튼은 아이콘과 위치도 선택하며 기본·비활성·로딩 상태를 비교합니다.
- 미리보기와 React 소스가 함께 변경됩니다. 코드에는 CSS 변수 fallback과 상호작용 스타일을 포함하므로 Tailwind 없이도 사용할 수 있습니다. 아이콘을 선택한 버튼은 lucide-react 의존성이 필요합니다.
- `/design/saved`: 현재 브라우저에 디자인을 저장하고 다시 열기·수정·삭제합니다. 서버 동기화는 제공하지 않습니다.
- `/components?group=...`: 버튼/폼/데이터/탐색/피드백/표시 분류별로 기존 UI를 탐색합니다.
- `/setup`: 실제 package.json의 버전, Windows/WSL 설치, 폴더 역할, Spring Boot 등의 API 연결 예시, 환경변수, 정적 배포, 문제 해결을 설명합니다. Markdown 가이드를 내려받을 수 있습니다.
- 독립 생성 ZIP의 README에도 실제 선택된 의존성 버전, 설치/구조/API/배포 안내와 .nvmrc를 포함했습니다.

확장 검증: TypeScript와 프로덕션 빌드, Vitest 54개(디자인 소스 16개 추가), 6개 독립 생성 프로젝트를 검증합니다. 이번 변경의 UI는 Sites 관리 미리보기와 cloud browser에서 직접 확인합니다. 이전 버전의 Playwright 14개 통과 기록은 위에 보존했으며 이번 변경을 대상으로 Playwright를 다시 실행했다는 의미는 아닙니다.

## 완성형 템플릿 중심 UX 전환

- 기본 홈을 업무 템플릿 12종으로 교체했습니다. 공통 엔진에 업무별 필드·상태·데이터를 제공하며 6종의 화면 패턴을 지원합니다. 기존 기술 샘플 3종은 /examples로 이동했습니다.
- /compose/:id에서 6개 빠른 구성을 클릭하거나 저장한 내 구성을 적용합니다. 메뉴 위치, 표/카드, 요약/필터/활동/차트 블록을 즉시 전환하고 되돌리기·기본값 복원을 제공합니다. 이름/색상 설정은 접힌 영역에 둡니다.
- /my-templates는 브라우저에 저장한 화면 구성을 불러오고 수정/삭제합니다. 다른 업무 화면에 내 구성을 적용할 때 화면의 업무·제목·서비스 이름은 유지합니다. 서버 간 동기화는 없습니다.
- 내보내기 ZIP에는 현재 구성과 실제 공통 화면 구현/model/CSS를 포함합니다. 12개 신규 업무 템플릿과 기존 옵션별 6개를 합쳐 18개의 독립 설치/빌드/테스트를 검증합니다.
- 이번 변경의 단위 검사 79개 통과. 타입·프로덕션 빌드 통과. CUA 관리 브라우저에서 프리셋 적용, 메뉴/카드 전환, 저장 후 재편집, 다른 업무에 구성 재사용, Mock 회원 등록/검색을 확인했습니다. 새 Playwright 시나리오는 CI용으로 추가했으며 관리 브라우저 경로 밖에서 직접 실행하지 않았습니다.

## 회사 표준 UI와 AI 조합 참조 구현

- `/company-kit`: 공통 컴포넌트 명세 23개, 실제 회원 관리, 조합 코드, AI 요청 예시, 독립 설치 ZIP을 제공합니다. registry JSON을 UI와 배포 ZIP이 함께 사용합니다.
- `@hub/ui-core` / `@hub/screen-patterns` 0.1.0: Vite library mode의 ESM, TypeScript 선언, 사전 빌드 CSS를 tarball로 배포 ZIP에 포함합니다. React는 peer dependency이며 번들에 중복 포함하지 않습니다. 외부 npm registry 게시 작업은 하지 않았습니다.
- `ListPage`는 검색·필터·목록·페이지 이동·로딩·오류/재시도를 조합합니다. `FormDialog`는 폼 제출과 Radix 모달을 조합합니다. 데이터 조회와 상태는 소비자가 소유합니다.
- 독립 예제는 회원 검색·상태 필터·페이지 이동·등록·수정·중복 이메일 검증을 제공합니다. Mock 데이터는 메모리입니다. UI 구현 파일을 복사하거나 저장소 alias로 참조하지 않고 두 tarball을 설치합니다.
- `pnpm check:ui`: TypeScript AST로 승인 import/export, JSX 태그, 속성 우회, CSS 파일, 동적 생성의 일반적 사례를 검사합니다. CLI는 승인된 부트스트랩에서만 앱 진입점·root 연결을 허용합니다. 정책은 보안 샌드박스가 아니며 정책 파일·패키지 변경은 코드 리뷰 대상입니다.
- `pnpm verify:consumer`: ZIP을 저장소 바깥 임시 디렉터리에 풀어 패키지 설치·타입 검사·프로덕션 빌드·설치된 패키지 SSR을 검증합니다. CI에도 같은 절차를 추가했습니다.
- 기존 12종 템플릿은 여전히 소스 생성 경로입니다. 전체 템플릿의 strict 패키지 조합 전환, 회사 디자인 승인, 사내 registry 연결, API 연동과 버전 업데이트 운영은 남아 있습니다. 별도 AI 스킬이나 MCP 서버는 이번 변경에 포함하지 않았습니다.

이번 검증: 타입·프로덕션 빌드, Vitest 94개, UI 정책 검사, 독립 소비자 설치/빌드/SSR 및 위반 버튼 거부를 통과했습니다. CUA 관리 브라우저에서 등록·검색·수정과 명세 검색/선택을 확인했습니다. Playwright 회사 키트 시나리오는 CI용으로 추가했으며 이번에는 별도 Playwright 실행 없이 관리 브라우저로 확인했습니다.
